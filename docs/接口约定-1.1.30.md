# 接口约定 v1.1.30（原生层 ↔ 控制台 ↔ 沙盒层 ↔ 服务端）

本文件是 v1.1.30 这一版的跨层契约，**先定协议再实现**，各方照此写，不许各自发明字段。
任何一方想改字段，先改本文件并通知其他层。

## 0. 通用约定

- 全部挂在 `window.Android` 下（`QqbotBridge.java` 的 `@JavascriptInterface`）。
- 一律返回 **String**，内容是 JSON：成功 `{"ok":true,...}`，失败 `{"ok":false,"err":"中文原因"}`。
  前端必须同时处理 `ok:false` 与 `JSON.parse` 失败（返回空串/`null` 时按失败处理）。
- 所有读取类接口**必须 <50ms 返回**，不许在主线程做 IO / 网络 / 起进程：
  数据由后台线程周期刷新到内存缓存，接口只读缓存。
- 所有会阻塞的动作（备份、恢复、清理、抓公告）都是 **start/poll 两段式**：
  `xxxStart(...)` 立刻返回 `{"ok":true,"started":true}`，`xxxPoll()` 返回进度。
- 字段名一律小写驼峰；时间戳一律 **epoch 秒**（`long`），时长一律 **秒**（`int`）。
- 新增接口只增不改；老字段含义不变。

## 1. 今日概览（功能 15）

```json
todayStats() -> {"ok":true,"day":"2026-10-19","onlineSec":7320,"msgs":184,
                 "errors":3,"rxBytes":1234567,"txBytes":234567}
```

- `onlineSec`：守护心跳累计（`$QQBOT_HOME/state/heartbeat` 秒数账本，跨天清零）。
- `msgs`：`/root/astrbot/data/*.log` 与 `/qqbot-cache/logs/astrbot.log` 里收发消息行计数，容差 ≤5%。
- `errors`：同期 `[error]`/`Traceback` 行数。
- 流量：`TrafficStats.getUidRxBytes(Process.myUid())` 累计值换算，跨天记基线。
- 持久化：`$QQBOT_HOME/state/today.json`（原生写，沙盒只读不写）。

## 2. 风控识别（功能 4）

沙盒层产出，原生层只读：

```json
riskInfo() -> {"ok":true,"risk":true,"instance":"bot1","word":"登录异常",
               "line":"...","since":1760900000,"file":"/qqbot-cache/logs/qq-bot1.log"}
riskClear() -> {"ok":true}
```

- 沙盒层：`sandbox/risk-words.txt`（一行一个词，`#` 注释，可热改）＋巡检脚本命中后写
  `$QQBOT_HOME/state/risk.json`（同上字段），并给该实例打 `$QQBOT_HOME/state/risk-<id>.flag`
  让重启循环停下。
- 原生层：`riskInfo()` 读 `risk.json`；`riskClear()` 删 `risk.json` 与所有 `.flag`（UI 的「我知道了」）。
- UI：`risk:true` 时顶部红色横幅，文案要区分「需要验证/被踢下线」与「进程崩溃」。
- 通知：命中时发一条通知（channel `qqbot_risk`），文案「实例 X 可能需要验证，已暂停自动重启」。

## 3. 网络切换自愈（功能 2）

```json
netInfo() -> {"ok":true,"online":true,"type":"wifi","lastSwitch":1760900000,"recoveries":2}
```

- 原生 `NetworkWatch.java` 注册 `NetworkCallback`，只在「无网→有网」或默认网络切换时触发，
  30 秒 debounce，然后走既有服务重启入口；顺序固定：先等 NapCat 端口可连，再启 AstrBot。
- 不新增权限（`ACCESS_NETWORK_STATE` 清单里已有）。

## 4. 紧急下线（功能 9）

```json
emergencyStop()  -> {"ok":true}
emergencyResume() -> {"ok":true}
```

- 复用 `stop-sandbox.sh` / 守护启动入口；**绝不碰** QQ 配置、AstrBot data、实例配置。
- 停完写 `$QQBOT_HOME/state/offline`（内容为时间戳）；`emergencyResume()` 删标记并拉起守护。
- 三处入口（主页顶部、通知栏 Action、更多页）调同一个方法。

## 5. 通知栏常驻卡片（功能 11）

不涉及 JS。原生 `QqbotGuardService` 用 `NotificationCompat`：

- ContentTitle：`烛之控制台 · N 个实例在线`
- ContentText：`NapCat ✓ AstrBot ✓` 或具体掉线条目
- Action 1「重启」→ service action `com.termux.qqbot.ACTION_RESTART`（PendingIntent.getService）
- Action 2「看日志」→ Activity extra `tab=logs`
- Action 3「扫码」→ Activity extra `tab=bot`
- 30 秒或状态变化时 `notify`；停服务时 `stopForeground(true)` 后 `cancel`。

## 6. 桌面小组件（功能 12）/ 快捷磁贴（功能 13）

- 状态源：`$QQBOT_HOME/state/ui.json`（原生写，字段 `online`/`total`/`serviceAlive`/`updated`）。
- 小组件 `QqbotWidgetProvider`：点击 → `QqbotActivity`；`data-act=toggle` 按钮 → 广播
  `com.termux.qqbot.WIDGET_TOGGLE` 由 `QqbotGuardService` 处理（启/停守护）。
- 磁贴 `QqbotTileService`：`onClick` 读 `serviceAlive` 决定启停，失败回滚 + toast。
- 注册：`res/xml/widget_info.xml`、`res/layout/widget_status.xml`；Manifest 加
  `android.appwidget.provider` 与 `BIND_QUICK_SETTINGS_TILE`（API 24+，加 `android:enabled` 保持低版本兼容）。

## 7. 存储占用（功能 54）

沙盒层 `du` 固定目录 → `$QQBOT_HOME/cache/storage.json`：

```json
{"ts":1760900000,"total":123456789,"dirs":[
  {"key":"rootfs","name":"容器","path":"/root/ubuntu","bytes":1},
  {"key":"astrbot","name":"AstrBot","path":"/root/astrbot","bytes":1},
  {"key":"plugins","name":"插件","path":"/root/astrbot/data/plugins","bytes":1},
  {"key":"logs","name":"日志","path":"/qqbot-cache/logs","bytes":1},
  {"key":"qq","name":"登录数据","path":"/root/qqinst","bytes":1}],
 "top":[{"path":"/root/astrbot/data/x.db","bytes":12345}]}
```

原生层（全部在后台线程跑脚本，主线程零文件遍历；结果缓存到 `state/storage.json`）：

```json
storageStats() -> {"ok":true,"warm":true,"stale":false,"ts":1760900000,"total":123,
                   "dirs":[{...}],"top":[{...}],"src":"shell","lastErr":""}
storageRefreshStart() -> {"ok":true,"started":true}
storageClean() -> {"ok":true,"freed":123,"kept":["登录数据","配置","插件"],"log":"[storage] 清理完成：…"}
```

- 首次没有缓存时立刻回 `warm:false`、`dirs`/`top` 为空，后台跑一次脚本；缓存超过 60 秒时
  先回旧数据（`stale:true`）再重算，所以桥调用从不阻塞。
- `storageInfo` / `storageRefresh` 是 `storageStats` / `storageRefreshStart` 的别名，前端写哪个都行。
- 脚本没有「可清理量」这个数，故不返回 `cleanable`（硬编 0 会误导）。
- 清理只清 `apt/pip/npm` 缓存、`/root/.cache`、`/tmp`、`*.log.1`；**不动**登录数据/配置/插件。
  沙盒正在跑时脚本自己跳过 proot-tmp，`log` 里会说明。
- `top` 最多 10 条，`bytes` 一律字节。

## 8. 一键备份 / 恢复（功能 50）

沙盒层 `backup.sh` / `restore.sh`（已实现并自测，原生侧只调用，不重写逻辑）：

- `backup.sh <scope> <out.tar.gz>`：scope ∈ `all|config|plugins`；打包 AstrBot data（排除 logs/cache）、
  插件目录、NapCat 登录数据、实例配置；成功在 stdout 打一行 `SHA256=<hex>` 并退 0，
  失败打 `ERR=<原因>` 并退 1；进度写 `$QQBOT_HOME/state/backup.pct`（`0..100` / `done` / `error`）。
  输出目录由脚本自己 `mkdir -p`，传绝对路径即可。
- `restore.sh <scope> <in.tar.gz> [SHA256=<hex>] [snapshot.tar.gz]`：恢复可选范围；**只有传了 `SHA256=` 才校验**；
  没给快照就先现打一个 `all` 快照进 `$QQBOT_CACHE/tmp/pre-restore-<ts>.tar.gz`（内部会调 backup.sh，
  顺带覆盖 `backup.pct` 和上一轮的 sha）；成功输出 `OK`、失败输出 `ERR=<原因>`。
  **停服由脚本自己做**（`stop-sandbox.sh --no-offline`），原生侧不要再预停：脚本要靠「原本在跑」这个状态
  决定恢复后重启服务，预停会让 WAS_RUNNING=0，恢复完服务就起不来了。

原生层（SAF，不写死路径、不申请存储权限；阻塞动作一律 start + poll）：

```json
backupStart()            -> {"ok":true,"started":true,"scope":"all","name":"astrbot-backup-20261019-1600.tar.gz"}
backupStartScope(String) -> 同上，scope: all|config|plugins
backupPoll()             -> {"ok":true,"state":"idle|running|done|error","pct":42,
                             "name":"…","file":"…","size":123456,"sha256":"…",
                             "scope":"all","saved":false,"product":true,"err":"","ts":1760900000}
backupPick()             -> {"ok":true,"started":true}      // 把已生成的产物「另存为」到用户挑的 URI
backupInfo()             -> {"ok":true,"last":{…},"restoreLast":{…},
                             "backupState":"done","restoreState":"idle","pct":100,
                             "srcBytes":123456789,"srcKnown":true,"srcTs":1760900000,"busy":"","ts":1760900000}
restorePick()            -> {"ok":true,"started":true}      // 选包：只拷进缓存并算 sha，不直接开跑
restorePickScope(String) -> 同上，scope: all|config|plugins
restoreApply()           -> {"ok":true,"started":true}      // 前端二次确认后才调，真正开跑
restorePoll()            -> {"ok":true,"state":"idle|picked|running|done|error","pct":42,
                             "name":"…","size":123456,"sha256":"…","scope":"all",
                             "needConfirm":false,"picked":false,"err":"","ts":1760900000}
```

- 选包成功、包已拷进缓存后，原生推 `window.restorePicked(json)`：
  `{"ok":true,"scope":"all","name":"…","size":123456,"sha256":"…","needConfirm":true}`；
  「另存为」完成后推 `window.backupPicked(json)`：`{"ok":true,"saved":true,"name":"…","size":123456,"sha256":"…"}`；
  用户中途取消推 `{"ok":false,"err":"cancelled"}`。前端没挂这两个回调也不会报错（推之前查 typeof），`poll` 仍可兜底。
- 备份用 `ACTION_CREATE_DOCUMENT`（`application/gzip`，默认名 `astrbot-backup-<yyyyMMdd-HHmm>.tar.gz`，
  不套 `createChooser`：包一层会丢掉「新建文件」语义）；恢复用 `ACTION_OPEN_DOCUMENT`
  （`*/*` + MIME 白名单 `application/gzip|x-gzip|x-tar|octet-stream`）——不写死 `application/gzip` 是因为
  部分文件管理器把 `.tar.gz` 报成 `octet-stream`，写死会让合法备份在选文件界面变灰。
- 中间文件：备份写 `$QQBOT_HOME/cache/tmp/<name>`，另存成功后删除；恢复把包拷到
  `$QQBOT_HOME/cache/restore/`（覆盖前先清空），恢复成功即删、失败保留（`picked` 仍为 true，可直接重试）。
- 状态落 `state/backup.json` / `state/restore.json`；`pct` 只在 `running` 时读 `state/backup.pct`，
  结束态一律给 100、`idle` 给 0。
- `state` 停在 `running` 且 `ts` 超过 30 分钟没更新时对外降级为 `error`（进程被系统杀掉后不会永远转圈）。
- `size` / `srcBytes` 单位字节；`srcBytes` 由后台线程有界遍历 + 60 秒缓存得出，`backupInfo()` 本身不做重 IO。

## 9. 崩溃聚合看板（功能 58）

沙盒层 `crash-agg.sh`：扫 `$QQBOT_CRASH_DIR/*.txt`（crashwatch 产出），
按「组件 + 崩溃签名」归并（签名 = 去掉地址/时间/pid 后的 pc 偏移 + 模块名 + 信号，取 sha1 前 12 位），
写 `$QQBOT_HOME/cache/crash-counts.json`：

```json
{"ts":1760900000,"classes":[{"sig":"a1b2c3d4e5f6","component":"napcat",
  "signal":"SIGSEGV","count":5,"first":1760000000,"last":1760900000,
  "ver":"1.1.29","device":"24069RA21C","samples":["path1","path2","path3"]}]}
```

原生层（读这个文件 + 存开关；开关开着时真的上报，见下）：

```json
crashInfo()  /  crashBoard()  -> {"ok":true,"on":false,"ts":1760900000,
                                  "classes":[{"sig","component","module","signal","count","first","last","ver","device","samples"}],
                                  "items":[{"sig","module","signal","count","last"}],
                                  "total":12,"kinds":3}
crashReportOn(boolean) / crashUploadSet(boolean) -> {"ok":true,"on":true,"enabled":true}
crashReportState()            -> {"ok":true,"on":false,"enabled":false,"ts":0,
                                  "atomOn":true,"lastSentDay":"","lastErr":"","lastAt":0}
crashUploadNow()              -> {"ok":true,"queued":true,"ts":1760900000}
crashClear()                  -> {"ok":true,"cleared":1}
```

- 文件不存在（从没崩过）返回 `{"ok":true,…,"classes":[],"items":[],"total":0}`，**不返回 err**。
  读取顺序 `cache/crash-counts.json` → `state/crash-counts.json`（兼容老布局）。
- 脚本里叫 `component`，面板按 `module` 取：所以同一个值两个字段都给。
- 开关写 `state/prefs.json` 的 `crashReport`，默认 `false`。**开关关着时原生层一个字节都不发**：
  上报任务的第一行就判断开关并直接 return，连 DNS 都不解析。
- 开关打开后有三个触发时机，都在后台线程（主线程零网络）：
  冷启动（`QqbotActivity.onCreate`）、守护线程每 6 小时巡检（`QqbotGuardTask.afterTick`，且要求 `NetworkWatch` 认为有网）、
  用户手动点 `crashUploadNow()`。
- 上报端点 `POST https://xn--15t839a.xyz/api/crash`，每个聚合类一条，**单次最多 20 条**；
  连接超时 5000ms、读超时 8000ms、不跟随重定向、失败不重试（等下一个时机）。body 只有这六个字段：

```json
{"id":"<安装 ID>","ver":"1.1.30","sig":"a1b2c3d4e5f6","module":"napcat","signal":11,"count":5}
```

  - `id` 取 `state/stats-id`（匿名统计安装 ID）；统计关着时退回 `state/atom-id` 里持久化的 UUID（首次生成后一直用）。
  - `module` 就是本地 counts 里的 `component`（脚本叫法），空则填 `"unknown"`。
  - `signal` 是 **POSIX 信号号整数**（SIGSEGV=11、SIGABRT=6、SIGBUS=7…，认不出给 0）；
    本地 `crashInfo()` / `crashBoard()` 里的 `signal` 仍是字符串（`"SIGSEGV"`），两处口径不同别混用。
  - 请求头必须带 `X-Qqbot-Atom: 1`（缺这个头服务端返回 403），`Content-Type: application/json; charset=utf-8`。
  - 只发上面六个字段：不发 IP / 时间戳 / pid / 日志正文 / QQ 号 / token。
- 每天最多成功一次：`state/upload.json` 的 `crashDay` 记最后成功日（= `crashReportState()` 的 `lastSentDay`）；
  失败只在该文件记 `lastErr` / `lastAt` / `lastCode`，不弹 toast、不写日志刷屏。
- `crashUploadNow()` 在开关关闭时返回 `{"ok":false,"err":"崩溃上报开关是关的","queued":false}`（不发、不解析 DNS）；
  打开时立刻返回 `{"ok":true,"queued":true,"ts":…}` 并起后台线程**真发一次**（不受「今天已发过」限制），
  成功后把 `state/upload.json` 的 `crashDay` 置为今天。
- `crashClear()` 把两个布局的 counts 文件都删，`cleared` 是实际删掉的个数。

## 10. 匿名统计（功能 59）

原生层维护「开关 + 一个随机安装 ID」；开关打开时每天上报一条今日概览（见下）：

```json
statsOn(boolean) / statsSet(boolean) -> {"ok":true,"on":true,"enabled":true,"id":"uuid4","installId":"uuid4","day":"2026-10-19"}
statsId() / statsState()             -> {"ok":true,"on":false,"enabled":false,"id":"","installId":"","day":"2026-10-19","ts":0,
                                         "atomOn":true,"lastSentDay":"","lastErr":"","lastAt":0}
statsReset()                         -> {"ok":true,"id":"uuid4","installId":"uuid4","on":true,"enabled":true}
statsEvents()                        -> {"ok":true,"on":false,"events":[],"todaySec":123,"day":"2026-10-19"}
```

- 默认关闭。未开启时 `id` / `installId` 都是空串（前端据此显示「未开启」，而不是一个幽灵 ID）。
- 首次开启且没有 `state/stats-id` 时生成 `UUID.randomUUID()` 落盘（纯文本一行）；`statsReset()` 直接换新 ID。
- 关闭时不改已生成的 ID（下次开启还是同一个安装），**不发任何请求、连 DNS 都不解析**，也不清已有数据。
- `statsEvents()`：原生层不落事件表，`events` 恒为空数组；`todaySec` 取 `state/today.json` 的 `onlineSec`。
- 上报端点 `POST https://xn--15t839a.xyz/api/stats`，`Content-Type: application/json; charset=utf-8`，
  请求头必须带 `X-Qqbot-Atom: 1`（缺则 403），连接超时 5000ms / 读超时 8000ms / 不跟随重定向 / 失败不重试：

```json
{"id":"<安装 ID>","ver":"1.1.30","day":"2026-10-19","onlineSec":123,
 "msgs":4,"errors":0,"os":"Android 34","arch":"arm64-v8a","events":{"open":7}}
```

  - `onlineSec` / `msgs` / `errors` 取 `state/today.json`；若它的 `day` 与今天不同就全给 0，避免把昨天的数记到今天。
  - `events.open` 是冷启动累计次数（`state/stats-open`，每次冷启动 +1，只增不减；`statsReset()` 不动它）。
  - `os` = `"Android " + Build.VERSION.SDK_INT`，`arch` = `Build.SUPPORTED_ABIS[0]`。
- 一天只发一条：`state/upload.json` 的 `statsDay` 记最后成功日（= `statsState()` 的 `lastSentDay`），同一天已成功就不再发；
  失败只记 `lastErr` / `lastAt` / `lastCode` 并静默等下次（冷启动或每 6 小时巡检）。
- 触发时机与崩溃上报一致：冷启动、守护线程 6 小时巡检（要求有网）；统计没有单独的手动上报入口。

## 11. 公告 / 远程配置（功能 56）

服务端（D 层）优先 `GET https://xn--15t839a.xyz/api/announce?ver=<versionName>`，带
`X-Qqbot-Atom: 1`（缺了 403）与 `ETag`；服务端还没铺这条路径时，原生层收到 4xx/5xx 会自动退到
老契约的 `GET /api/app-config.json`（同一份 `ETag`）。

```json
{"ver":1,"minVer":"1.1.0",
 "items":[{"id":"20261019-1","title":"标题","body":"公告正文","level":"info","minVer":"","until":1761000000},
          {"id":"20261019-2","title":"…","body":"…","level":"warn","until":"2026-12-31"}]}
```

老契约的 `{"ver":1,"minVer":"1.1.0","ann":{…},"flags":{…}}` 也认，原生层归一成 `items[0]`；
`flags` 不落地（前端没读），只透传 `ver` / `minVer`。

原生层（后台线程、GET 5 秒超时、失败静默、结果缓存到 `state/ann.json`）：

```json
ann() -> {"ok":true,"warm":true,"cached":true,"stale":false,"ts":1760900000,
          "items":[{...}],"ver":1,"minVer":"1.1.0","lastErr":""}
annRefreshStart() -> {"ok":true,"started":true}
```

- 首次没有缓存时立刻回 `items:[]`、`warm:false`，后台抓一次；`stale:true` 表示这是旧数据。
- 请求带 `If-None-Match: <上次的 ETag>`；**304 → 只更新 `ts`，`items` 原样保留**；
  200 → 覆盖 `items` 与 `etag`；失败只写 `lastErr` / `lastAt`，界面继续显示上一次的公告。
- 距上次成功刷新不足 5 分钟不发请求（前端也是 5 分钟问一次）；`annRefreshStart()` 强制。
- 隐私：只发版本号，不带安装 ID、机型或任何设备标识。
- `until` 统一成 **epoch 秒**（服务端给 `"YYYY-MM-DD"` 时按当天 23:59:59 折算；认不出给 0 = 永不过期，前端按秒比较）。
- 公告为可关闭顶部条（关闭记 `ann.id` 到 localStorage）。
- `minVer` 只提示不强制；非法字段整条忽略，不抛错；断网启动必须无报错无卡顿。

## 12. 实例卡片（功能 17）

```json
avatarPath(String uin) -> {"ok":true,"path":"file:///data/.../avatars/123456.png","cached":true}
```

- 原生后台下载 `https://q1.qlogo.cn/g?b=qq&nk=<uin>&s=100` 到
  `$QQBOT_HOME/cache/avatars/<uin>.png`，LRU 上限 50 个；断网时 `cached:false` 且 `path` 为空。
- 掉线时间/启动时间：`$QQBOT_HOME/state/instances.json`（原生写）：
  `{"bot1":{"started":1760900000,"lastOffline":1760950000,"uin":"10001","nick":""}}`
