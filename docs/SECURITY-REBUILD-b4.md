# 全量包安全重制说明（2026-10-29）

> 适用对象：下载或安装过 2026-10-29 之前发布的全量包（文件名不带 `-update`）的用户。
> 增量更新包不含离线镜像，不受本次问题影响。

## 发生了什么

2026-10-29 之前发布的全量包，在 `assets/qqbot-bundle.tar.xz` 离线镜像里误带了构建机上的运行期数据。受影响范围：

- 1.3.1、1.3.2（含 1.3.2-beta.1 / beta.2）、1.3.3（含 beta.1 … beta.10）、1.3.4（含 beta.1 … beta.10）的全量包；
- 1.3.5-beta.1 / beta.2 / beta.3 的全量包。

误带的 24 个条目包括：

- AstrBot 的 `data/cmd_config.json`：dashboard 账号相关字段、`password` / `pbkdf2_password`、固定的 `jwt_secret` 与管理员 ID；
- AstrBot 的 `data_v4.db`（含 `-wal` / `-shm`）与知识库 `kb.db`；
- 运行日志、插件配置、附件 / webchat / 临时目录；
- NapCat 的 `config/webui.json`（含 WebUI token）、`onebot11.json`、`napcat.json`；
- 一张打包前约 15 分钟生成的 NapCat 登录二维码。

这些文件是打包那台机器当时正在使用的真实配置与数据（不是你手机里的聊天记录或配置），不是给新用户准备的模板。拿到旧全量包的人，可能从中读到上述值。

## 已经做了什么

- 从镜像中删除 24 个运行期条目，重新压缩出干净的 arm64 / amd64 镜像：
  - arm64：`583,012,780 B`，SHA-256 `283795c16894abfab1582060e1fdea8239a6cfe896e6b84c5de97519ed78fd91`；
  - amd64：`571,602,828 B`，SHA-256 `3ea65835df037ea06a6a8855e189cdcb1c858e147e01aa17a9ca796caf2b4ca7`。
- 1.3.5-beta.4 与 1.3.4 两个全量包已用干净镜像重制；1.3.4 保持 `versionCode 10304`、界面不变，可直接覆盖安装。
- 其余 28 个受影响的全量包资产已从 GitHub Release 下架，并在对应 Release 正文加了安全公告；增量包全部保留。
- 官网 `/downloads/` 只保留重制后的 1.3.4 全量包，下载卡的 SHA-256 已同步。

## 建议尽快做的四件事

更新应用不会自动改掉已经部署在手机里的旧配置，需要手动轮换一次：

1. **改 dashboard 密码**：打开 AstrBot 管理面板，在账号安全里换一个新密码，不要与其它网站重复。
2. **让 JWT 重新生成**：退出登录，删除 / 重置旧 `jwt_secret`，重启 AstrBot；下次启动会自动生成新值，旧登录态全部失效。
3. **换 NapCat WebUI Token**：在 NapCat 的 WebUI 设置里重新生成 Token，保存后重启 NapCat。
4. **重新登录 QQ**：在 NapCat 里退出当前账号再扫一次码；旧二维码本身只有几分钟有效期，重新登录后彻底作废。

## 怎么确认生效

- 旧 dashboard 密码登不上；
- 旧设备 / 旧浏览器里的登录态被踢下线；
- 旧 NapCat Token 鉴权失败；
- 重新扫码后，运行状态与消息收发正常。

这四步不会动聊天记录、插件和已部署的数据。没有分发过旧全量包、也不担心手机外借的用户，风险相对有限，但仍建议完成一次轮换。

## 安装建议

- 已经装过旧版：直接覆盖安装重制后的 1.3.4 全量包，或使用 `AstrBot-1.3.5-beta.4-arm64-update.apk`；装完按上面四步轮换。
- 新用户：只下载重制后的 1.3.4 全量包，不要使用任何旧的全量包副本。
- 校验：1.3.4 设置里看 `versionCode 10304`，1.3.5-beta.4 看 `versionCode 10305`，并用上面的 SHA-256 核对文件。
- 如果手里还留着旧全量包，请直接删除，不要继续安装或转发。
