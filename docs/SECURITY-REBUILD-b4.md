# 1.3.5-beta.4 全量包安全重制说明

> 适用对象：装过 1.3.5-beta.3 或 1.3.5-beta.4 **全量包**（文件名不带 `-update`）的用户。
> 增量包不含离线镜像，不受本次问题影响。

## 发生了什么

2026-10-29 之前发布的 1.3.5-beta.3 / beta.4 全量包，在 `assets/qqbot-bundle.tar.xz` 离线镜像里误带了构建机上的运行期数据：

- AstrBot 的 `data/cmd_config.json`：包含 dashboard 账号相关字段、`password` / `pbkdf2_password`、固定的 `jwt_secret` 与管理员 ID；
- AstrBot 的 `data_v4.db`（含 `-wal` / `-shm`）与知识库 `kb.db`；
- 运行日志、插件配置、附件 / webchat / 临时目录；
- NapCat 的 `config/webui.json`（含 WebUI token）、`onebot11.json`、`napcat.json`；
- 一张打包前约 15 分钟生成的 NapCat 登录二维码。

这些文件是构建机当时正在使用的真实配置，不是给新用户准备的模板。拿到旧全量包的人，可能从中读到上述值。

## 已经做了什么

- 从镜像中删除 24 个运行期条目，重新压缩、重新构建全量 APK；
- 新包只保留可公开的运行环境与 `t2i_templates` 等必要文件；
- 新全量包已替换 GitHub Release 上的旧资产，版本号仍为 `1.3.5-beta.4`（`versionCode 10305`），功能不变。

## 建议尽快做的四件事

更新应用不会自动改掉已经部署在手机里的旧配置，需要手动轮换一次：

1. **改 dashboard 密码**：打开 AstrBot 管理面板，在账号安全里换一个新密码，不要与其它网站重复。
2. **让 JWT 重新生成**：退出登录，删除 / 重置旧 `jwt_secret`，重启 AstrBot；下次启动会自动生成新值，旧登录态全部失效。
3. **换 NapCat WebUI Token**：在 NapCat 的 WebUI 设置里重新生成 Token，保存后重启 NapCat。
4. **重新登录 QQ**：在 NapCat 里退出当前账号再扫一次码；旧二维码本身只有几分钟有效期，重新登录后彻底作废。

## 怎么确认生效

- 旧 dashboard 密码登不上；
- 旧设备 / 旧浏览器里的登录态被踢下线；
- 旧 NapCat Token 鉴权失败；
- 重新扫码后，运行状态与消息收发正常。

这四步不会动聊天记录、插件和已部署的数据。没有分发过旧全量包、也不担心手机外借的用户，风险相对有限，但仍建议完成一次轮换。

## 安装建议

- 已经装过旧版：直接覆盖安装新的全量包，或使用 `AstrBot-1.3.5-beta.4-arm64-update.apk`；装完按上面四步轮换。
- 新用户：只下载新的全量包，不要使用任何旧的全量包副本。
- 校验：设置里看 `versionCode 10305`，并用上面的 SHA-256 核对文件。
