> 这是一份「还能加什么功能」的候选池，共 200 条，按主题分成 13 组，编号 1-200 连续唯一。
> 用法：直接回编号就行，例如「做 12、37、88」，我会按你选的那几条去实现；也可以只报组名，如「先把稳定性那组做掉」。
> 难度是改造量粗估（低=几小时，中=几天，高=要加新依赖或动架构）；优先级是组内性价比排序，不是必须按顺序做。
> 条目之间基本独立，可以任意挑；少数有依赖关系（比如插件市场依赖插件启停）的，我会在动手前说明。

## 已有功能（不在候选内）

- 自动部署：打开应用即在手机内建 Linux 沙盒（Termux + proot Ubuntu 24.04），自动装好 NapCat 与 AstrBot，主页展示 8 步进度。
- 自动对接：NapCat 以 OneBot v11 反向 WebSocket 连 ws://127.0.0.1:6199/ws，装完即可用。
- 多实例：多个 QQ 号同时在线，各自独立配置/缓存/日志/登录数据，可新增、编辑、删除、设为当前、复制 Token、停止容器、显示二维码。
- 扫码登录：应用内直接显示真 PNG 二维码。
- 日志页：NapCat 与 AstrBot 并排实时日志、其它日志文件、清空、删除、精简模式。
- 外观：本机图片背景（长边 1600 自动压缩）、6 个预设、玻璃强度。
- 终端：内置终端入口。
- 设置页：组件重装 NapCat/AstrBot、端口设置与冲突避让、服务控制、维护、关于。
- 后台守护：supervisor 守护进程自动重启容器。

## 一、稳定性与自愈（18 条）

- **1. 容器崩溃自动重启退避** — proot 容器反复崩溃时按指数退避重启，避免崩溃循环把 CPU 和电量打满。（难度：低 · 优先级：高）
- **2. 部署断点续传** — 记录 8 步部署每步产物的校验和，中断后从失败那步继续，不重跑已完成的 apt 安装。（难度：中 · 优先级：高）
- **3. NapCat 掉线自愈** — OneBot 反向 WS 断开超过设定秒数就自动重启 NapCat 容器并提示重新扫码。（难度：中 · 优先级：高）
- **4. AstrBot 心跳看门狗** — 定期请求 6185 健康接口，连续无响应则重启 AstrBot 进程。（难度：低 · 优先级：高）
- **5. 实例故障隔离** — 某个 NapCat 实例崩溃不影响其它实例，各实例独立 supervisor 与资源限额。（难度：中 · 优先级：中）
- **6. 组件依赖自愈** — 检测沙盒内缺失的 python/node/pip 依赖并自动补齐，避免插件因缺包启动失败。（难度：中 · 优先级：中）
- **7. 存储空间不足保护** — 剩余空间低于阈值时暂停日志写入并弹通知，防止撑爆 /data 把容器写坏。（难度：中 · 优先级：高）
- **8. proot 挂载点自检** — 启动时检查 /proc、/dev、/sys 绑定挂载是否完整，缺失自动重建。（难度：中 · 优先级：中）
- **9. 安全模式启动** — 跳过所有插件与自动任务只起核心，用来排查插件导致的启动失败。（难度：中 · 优先级：中）
- **10. 网络切换自动恢复** — 监听 WiFi 与流量切换，网络变化后自动重连 NapCat 与 AstrBot。（难度：中 · 优先级：高）
- **11. 系统杀后台引导** — 检测应用是否被厂商省电策略冻结，并一步步引导加入白名单与自启。（难度：中 · 优先级：高）
- **12. 崩溃现场归档** — 应用或组件崩溃时把最后 500 行日志与堆栈写入带时间戳的文件。（难度：低 · 优先级：高）
- **13. 链路状态机视图** — 用 容器→NapCat→OneBot→AstrBot 四段状态图直观显示断在哪一环。（难度：中 · 优先级：中）
- **14. 定时自检任务** — 每 N 小时跑一次健康检查并留报告，只有异常才通知。（难度：低 · 优先级：中）
- **15. 容器时钟校正** — 检测沙盒内时间与主机偏差并同步，避免登录时间戳校验失败。（难度：中 · 优先级：中）
- **16. 卡死检测与强杀** — 进程长时间无 CPU 活动且无日志输出时判定卡死并自动强杀重启。（难度：中 · 优先级：中）
- **17. 启动依赖编排** — 保证 NapCat 先就绪、AstrBot 后启动，避免反向 WS 首次连接失败。（难度：低 · 优先级：高）
- **18. 组件版本回滚** — 升级后出问题一键回退到上一个可用版本快照。（难度：中 · 优先级：中）

## 八、性能与省电（15 条）

- **117. 前台服务优化** — 用低优先级前台服务维持进程，减少被系统回收。（难度：中 · 优先级：高）

- **123. 低电量模式** — 电量低于阈值时自动停用非关键实例并降低日志级别。（难度：低 · 优先级：中）
- **124. 内存上限与回收** — 给 AstrBot 设置内存上限并定期触发回收，防止 OOM 被杀。（难度：中 · 优先级：中）
- **125. 日志批量刷盘** — 日志批量写入而非逐行刷盘，降低 IO 与耗电。（难度：中 · 优先级：中）
- **126. 心跳合并** — 合并轮询请求、降低心跳频率，减少网络唤醒。（难度：低 · 优先级：低）
- **127. 部署耗时分析** — 展示 8 步部署各步骤耗时，找出慢在哪一步。（难度：低 · 优先级：中）
- **128. 页面按需加载** — 控制台分页懒加载，降低 WebView 内存占用。（难度：低 · 优先级：中）
- **129. 离线组件包** — 预置离线包减少首次部署的下载量。（难度：高 · 优先级：高）
- **130. 后台任务调度优化** — 用 WorkManager 替代自建定时器，跟随系统调度省电。（难度：中 · 优先级：中）
